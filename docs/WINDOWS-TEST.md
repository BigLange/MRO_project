# Windows 手动验证

先从工程根目录运行 `scripts/Test-Windows.ps1 -Package`。只有脚本成功后再进行下列界面测试；生成的报告是待验证的恢复版输出。

## 界面优先

1. 启动主程序与辅助程序，确认均能打开，Logo 和图标正常，没有资源加载异常。
2. 用相同 Windows 用户、字体、DPI 和窗口尺寸打开旧版与恢复版，对照显示效果。
3. 主窗口初始尺寸应为 1320×860，最小尺寸 1180×760；辅助窗口为 1260×820，最小尺寸 1080×720。
4. 对照顶部品牌区、状态卡、输入区、左右分栏、表格、问题汇总和日志卡片。检查滚动和窗口缩放，尤其在 100%、125%、150% DPI 下。
5. 检查按钮文字是否完整，有无表格被挤压或卡片内容被截断。恢复版调整过的按钮和说明文字见 `ui-recovery.json`，这些是有意变更。
6. 如出现 XAML 或资源异常，保留 `%LOCALAPPDATA%\MRO-Recovered\startup-errors.log`。视觉对照未通过前不能宣称与旧版一致。

## 标准库与错误路径

1. 主程序默认标准表指向随包的 `SharedContent/检测标准表.xlsx`。点击“导入标准库”，应显示 106 个产品，并提示数字条码、重复条码和旧版口径待法规复核事项。
2. 辅助程序点“重新加载”，应看到同一标准库数量。
3. 不选择称重表点击“分析文件”，应显示可读错误，界面保持可用。
4. 用原发布包 `W250905.xlsx` 测试：它的 6 个扫描码与标准表不匹配，应提示未知条码，且阻止报告导出。
5. 标准表条码 `0011010178`、`0011030039` 重复；不要期待本版自动选其中一个产品。

## 使用真实测量数据

1. 使用符合 README 表头要求的真实称重表，扫描条码必须在标准表中唯一。确认有 g 或 kg 单位。
2. 主程序“分析文件”后，核对产品、保留的条码前导零和实测记录数。填写真实生产数量（抽样基数）。
3. 点击“检查抽样数量”。例如批量 40 要求 32 条；不足时应提示缺测，不产生报告。批量 30 按旧版规则要求32条，应提示应抽数超过批量；150 应按旧版区间得到64条。
4. 数量和规则核对通过后“导出报告”。核对汇总的生产数量、应抽样数、实测数和平均值；低于规格的记录必须仍在明细中，来源行能回查。
5. 输出包含“汇总001”、“明细001_01”等产品页、“测量追溯”和“报告说明”；使用恢复的原表单样式。感官结果应为未录入、缺少生产日期应为未提供，所有判定须标明法规待复核。超过100条时应分页保留全部记录。
6. 辅助程序“导入实测Excel”，填写真实生产数量后检查并导出。把导出的实测表交给主程序再次导入，重量、条码和来源字段应保持一致。
7. 选择已存在的输出文件时，实际导出应拒绝覆盖。公式重量、未知单位、重复测量 ID、空条码或非正重量应阻止导入/导出。

## 保存结果

保留构建日志、`startup-errors.log`（如有），并记录 Windows 版本、DPI、通过/失败的步骤及实际错误。不要把 Core 运行检查通过视为 UI 对照通过。

## 本节点补充测试

- 导入生产表：先验证原 A/B 无表头格式，再验证命名表头/编码；检查未知、重复、缺量和与标准名称不符的错误。生产表中缺少称重记录的产品不能被静默省略。
- 修改输入输出目录后关闭并重开两个程序，检查路径恢复和字段互不覆盖；删除原文件后应回退。
- 使用安装 ZIP 的 Install-MRO.cmd 验证独立快捷方式与目录；关闭程序后卸载，确认恢复版数据仍保留。构建脚本不自动执行安装。
